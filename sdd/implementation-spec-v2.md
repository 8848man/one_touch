# v2 구현 명세

Figma `원터치카메라` 파일의 화면과 디자이너 주석을 기준으로, MVP SDD 대비 **v2에서 바뀌거나
추가되는 동작**만 정의한다. MVP 규칙을 다시 쓰지 않으며, 변경되는 규칙은 기존 문서 링크와 함께
"변경"으로 표시한다. Figma 주석에 근거가 없는 내용은 `**Assumption:**`, 디자이너가 `★`로 표시한
미결 사항은 `**Open:**`으로 표시한다.

> 이 문서는 v2 착수 전 합의용 초안이다. §9 Open 항목이 결정되면 해당 내용을 각 `feature/`·`fe/`
> 문서로 옮기고 이 문서는 인덱스로 축소한다 ([spec-authoring-guidelines](process/spec-authoring-guidelines.md)의 단일 책임 원칙).

## 3. 메인 카메라 화면 (S1)

Figma 주석 기준 영역 구성 (360×800, 상하 Safe Area 확보):

| 영역 | 요소 | 동작 | 주석 근거 |
|---|---|---|---|
| 상단 바 좌측 | 리스트 아이콘 | 앨범 리스트 화면(§4)으로 이동 | "앨범 리스트/새 앨범 추가/설정" |
| 상단 바 좌측 | `+` 아이콘 | 새 앨범 다이얼로그(§5) | 동일 |
| 상단 바 우측 | ⚙ | 설정(§7) | 동일 |
| 프리뷰 하단 | 카메라/동영상 토글 아이콘 | 촬영 모드 전환 | "기본 카메라/동영상 전환" |
| 하단 좌측 | 최근 사진 썸네일 | 현재 앨범의 최근 사진 열기 | "기본 카메라 앨범/사진촬영/앞뒤전환" |
| 하단 중앙 | 셔터 | 선택된 앨범에 저장 ([save-flow](feature/album/save-flow.md) 유지) | 동일 |
| 하단 우측 | 전·후면 전환 | 카메라 flip | 동일 |
| 앨범 칩 행 | 가로 스크롤 앨범명, 선택 칩은 강조색 + 상단 꼭지 | 좌우 스와이프로 앨범 이동 | "스와이프 이동" |

- **앨범명 길이 제한:** 칩에 표시할 때 일정 글자 수를 넘으면 말줄임 처리 (예: `260730_서울여행..`).
  **Assumption:** 칩 표시 최대 10자 + `..`. 저장되는 이름 자체는 자르지 않는다. 입력 최대 길이는 §9 Open.
- 플래시 버튼이 Figma 화면에 없다. **Open:** 플래시를 제거하는지, 다른 위치(설정·프리뷰 오버레이)로 옮기는지 결정 필요 ([camera-settings](feature/camera/camera-settings.md)는 플래시를 카메라 화면 런타임 컨트롤로 확정해 둔 상태).
- 썸네일 탭 시 동작은 Figma에 정의되지 않았다. **Assumption:** 앱 내 사진 보기가 아닌 OS 갤러리의 해당 앨범을 연다 (앨범 내 사진 보기는 roadmap-v2의 별도 기능이므로 구현 시 범위 재확인).

### 3.1 동영상 촬영 (신규)
- 토글로 `photo` ↔ `video` 모드 전환. 선택 상태는 강조색 원형 배경 아이콘.
- 동영상도 사진과 같은 저장 규칙(DR-3, DR-11)을 따른다. 녹화 중에는 앨범 스와이프를 막는다.
  **Assumption:** 녹화 중 앨범을 바꾸면 저장 위치가 모호해지므로 잠금.
- 마이크 권한이 추가로 필요하다 → [permission-handling](infra/permissions/permission-handling.md)에 마이크 거부 시 동영상 모드 비활성화 규칙 추가.
- 데이터 모델: `Photo` 대신 `Media { id, albumId, filePath, type: photo|video, createdAt }`로 일반화하거나 `Photo.type` 필드 추가. **Assumption:** 마이그레이션 비용이 적은 `Photo.type` 추가 방식 권장.

## 4. 앨범 리스트 화면 (S4)

모달에서 **전체 화면 라우트**로 바뀐다. 상단 바: 뒤로(←), ⚙. 본문 제목 "앨범 리스트".

### 4.1 행 구성
`[표시 토글] 앨범명 ………… [사진 수] [≡ 드래그 핸들]`

| 요소 | 규칙 | 근거 |
|---|---|---|
| 표시 토글 | MVP의 `isVisibleInLoop`와 동일 (DR-11~DR-14 유지) | — |
| 사진 수 | 1부터 표시, 0이면 숨김, 100 이상은 `100+` | "사진 개수 최대 100+ / 0은 보여주지 않음 1부터 시작" |
| 드래그 핸들 | 길게 눌러 순서 변경 → 카메라 앨범 칩 순서에 반영 | 화면 요소 (주석 없음) |

- 목록이 화면을 넘으면 세로 스크롤. "새로운 앨범 추가" 버튼은 하단에 떠 있는 FAB로 고정. ("뷰포트 이상 넘어가면 스크롤 처리")
- **변경 (DR-14):** 리스트에는 **앱에서 만든 앨범만** 표시한다 ("앨범리스트는 어플 내에서 작성한 것만 보여줄 것").
  MVP는 "앱이 인식하는 모든 앨범"(Camera 포함)이었다. **Open:** 기본 `Camera` 앨범을 리스트·칩에서 완전히 빼는지, 고정 항목으로 남기는지.
- 순서 저장: `Album.sortOrder: int` 필드 추가. 새 앨범은 맨 아래(마지막 순서)에 추가. **Assumption.**

### 4.2 스와이프 액션
행을 왼쪽으로 스와이프하면 오른쪽에 두 버튼이 나타난다: 연필(이름 편집, 연한 강조색), 휴지통(삭제, 강조색).
한 번에 한 행만 열려 있고, 다른 행을 스와이프하거나 바깥을 탭하면 닫힌다. **Assumption.**

## 5. 앨범 생성 (S2, S3)

- 진입점: 카메라 상단 `+`, 앨범 리스트 FAB. **변경:** [create-album](feature/album/create-album.md)의 "단일 진입점" 결정을 되돌린다.
- 다이얼로그: 제목 "새로운 앨범 추가", 텍스트 필드 1개, `취소` / `확인`. 다이얼로그가 떠 있는 동안 카메라 컨트롤은 딤 처리.
- `확인` → 앨범 생성 → **생성된 앨범으로 현재 위치 변경** (S3에서 선택 칩이 `앨범명` → `여행앨범`).
  ("확인을 눌러 앨범을 생성(추가) / 생성된 앨범으로 현재 위치 변경")
- 새 앨범의 표시 토글은 **on**으로 시작 ("새로운 앨범 (리스트) 추가 / 토글 : on"). MVP DR-15와 같은 동작이다.
- 중복 이름 검사(DR-4), 빈 이름 비활성화, Pending Album 처리(DR-9)는 MVP 그대로.

## 6. 이름 변경과 삭제

### 6.1 이름 변경 (S5) — DR-8 변경
흐름: 스와이프 → 연필 → 행이 텍스트 필드로 바뀌고 키보드가 올라옴, 오른쪽 버튼이 체크(✓)로 바뀜 → ✓ 또는 키보드 완료로 저장.

- 편집 중에도 토글 상태는 **사용자가 지정했던 값 유지** ("리스트 이름 편집 / 토글 : 기존에 유저가 지정했던 값 유지").
- 중복 이름 검사와 빈 이름 금지는 생성과 같은 규칙.
- **구현 방식 (DR-8 해결안):** Android에서 실제 폴더명을 바꾸는 API가 없으므로 다음 중 하나를 선택해야 한다.
  1. 앱 표시명만 변경 — `Album.displayName` 필드를 두고 기기 폴더명은 유지. 위험 없음, 단 OS 갤러리에서는 옛 이름으로 보임.
  2. 새 폴더로 미디어 이동 — `MediaStore` `RELATIVE_PATH` 갱신. Android 11+에서 다른 앱이 만든 파일이면 사용자 동의 필요, 대량 이동 시 시간 소요.

  **Assumption:** 1안을 기본으로 하고, OS 갤러리 이름까지 바뀌어야 한다면 2안을 별도 스파이크로 검증한다. **Open** (§9).

### 6.2 삭제 (S6) — DR-5 해제
흐름: 스와이프 → 휴지통 → 삭제 버튼이 행 너비로 확장(S6 `10`) → 확인 다이얼로그
제목 `앨범 삭제`, 본문 `{앨범명} 앨범을 삭제하시겠습니까?`, 버튼 `취소` / `확인` → 행 제거(S6 `12`).

- 삭제된 앨범이 현재 선택 앨범이었다면 DR-12 재선택 규칙을 적용하고, 마지막 앨범이었다면 DR-13 빈 상태로 간다.
- **Open (★ 디자이너 주석):** "삭제되는 앨범에 사진 데이터가 있는 경우 사진도 같이 삭제?"
  - (a) 앱 목록에서만 제거 — 기기 앨범과 사진 유지. 되돌릴 수 있음.
  - (b) 기기 앨범과 사진까지 삭제 — Android 11+는 `MediaStore.createDeleteRequest`로 시스템 동의 다이얼로그가 추가로 뜸. iOS는 `PHAssetCollectionChangeRequest` 삭제 시 시스템 확인.
  - 결정 전 기본값: **(a)**. (b)를 택하면 확인 다이얼로그 문구에 "사진 N장도 함께 삭제됩니다"를 넣어야 한다. **Assumption.**

## 7. 설정 (S8)

Figma `setting` 프레임은 아직 앨범 리스트와 같은 화면으로 채워져 있고, 실제 내용은 주석(Frame 14)에만 후보로 적혀 있다
("★설정에는 어떤 내용 들어가는지 확인"). 아래는 **후보 목록**이며 전부 Open이다.

| 후보 | 비고 | 판단 |
|---|---|---|
| 계정 / 계정 삭제, 앱 삭제 시 데이터 전부 삭제 여부 | MVP는 로그인 없음 (§4 제외) | 로그인 도입 전에는 "앱 삭제 시 앱 데이터(앨범 목록·순서·표시 상태)는 삭제되고 기기 사진은 남음" 안내만 |
| 요금제 안내 / 인앱 구매 / 구독 관리 | §8 무료 제한과 연결 | v2 포함 후보 |
| 앱 정보 (버전, 업데이트 확인) | MVP About 확장 | v2 포함 |
| 이용약관 | 인앱 결제 도입 시 필수 | v2 포함 (결제 도입 시) |
| 문의하기, 평가하기 | 외부 링크/스토어 리뷰 | v2 포함 후보 |
| 잠금 설정, 클라우드 백업, 기기 간 동기화 | 서버 필요, [be/future-scope](be/future-scope.md) | future |
| 리뷰 유도, 앱 추천, 초대 링크 | 마케팅 | 후보 |

[settings/overview](feature/settings/overview.md)의 경계(설정은 전역 환경설정만, 카메라 런타임·앨범 관리 금지)는 유지한다.

## 8. 무료 사용자 제한 (S7) — 신규

`free` 프레임: 앨범이 3개인 리스트 위에 "구매필요안내문구" 표시.

- **Assumption:** 무료 사용자는 앨범을 최대 3개까지 만들 수 있고, 4번째 생성 시도(카메라 `+` 또는 FAB) 때 구매 안내를 띄운다. 숫자 3은 화면의 행 수에서 추정한 값이다.
- 구매 안내 → 설정의 요금제/인앱 구매 화면으로 연결.
- 제한 기준(앨범 수 / 사진 수 / 기능), 결제 형태(1회 구매 / 구독)는 **Open**.
- 결제 상태는 로컬에 캐시하되 스토어 영수증으로 검증 (`in_app_purchase`). 신규 의존성이므로 [architecture/](../architecture/flutter_architecture.md) 리뷰 대상.

## 9. 폴더블 레이아웃 (S9) — 신규

| 상태 | 프레임 (760×844) | 구성 |
|---|---|---|
| 펼침 | Galaxy fold_expand | 왼쪽 세로 레일(⚙, 리스트, `+`), 가운데 프리뷰, 오른쪽 세로 컨트롤(전후면 전환, 셔터, 썸네일), 상단 사진/동영상 토글, 하단 앨범 칩 |
| 펼침 + 리스트 | Galaxy fold_close-interaction | 왼쪽 절반 앨범 리스트, 오른쪽 절반 카메라 화면(폰 레이아웃 그대로) |

- 화면 폭 기준(예: 600dp 이상)으로 레이아웃을 전환한다. 힌지 위치는 `MediaQuery.displayFeatures`로 판단. **Assumption.**
- 펼침 상태에서 리스트를 열면 화면 전환 대신 2분할로 보여 준다. 리스트에서 바꾼 표시/순서는 오른쪽 칩에 즉시 반영.

## 12. 구현 순서 (제안)

1. 데이터 모델 마이그레이션 (§10) + 앨범 리스트 전체 화면 전환 (§4, 정렬 포함)
2. 카메라 화면 레이아웃 개편 + `+` 생성 진입점 (§3, §5)
3. 이름 변경 1안 (§6.1) → O2 결정 후 필요하면 2안
4. 삭제 (§6.2) — O1 결정 후
5. 동영상 모드 (§3.1)
6. 설정 확장 (§7) → 무료 제한·인앱 결제 (§8)
7. 폴더블 레이아웃 (§9)

각 단계가 끝나면 해당 `feature/`·`fe/` 문서와 [domain-rules](core/domain/domain-rules.md)(DR-5, DR-8, DR-14, 로드맵 표)를 같은 변경에서 갱신한다.
